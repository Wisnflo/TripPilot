# Contributing

Use Python 3.12 and the locked uv environment. Run the offline checks from the README before proposing a change. Include the concrete behavior change, its reason and relevant validation in a pull request.

Changes to planning or scoring should include a minimal counterexample. Keep runtime predicted requirements separate from hidden benchmark annotations. For new empirical claims, specify task selection and budgets before observing outcomes; preserve failures, raw records and source and data version records.

Do not include credentials or private travel requests in issues, fixtures or evaluation artifacts. Report vulnerabilities through GitHub private vulnerability reporting when available; otherwise contact the maintainer before sharing sensitive details publicly.
